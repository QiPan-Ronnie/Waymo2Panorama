## 2. 三个必须知道的实测结论

### 2.1 🔴 Waymo Perception 的洞是 **130°，不是 108°** —— 我之前的数字错了

我此前按 `360 − 252 = 108°` 推算。**真实标定给出的是 130°**：

- 五个相机方位角：−89.9° / −45.1° / −0.1° / +45.3° / +90.2°
- 每个水平半 FOV = `atan(960/2055)` = **25.0°**
- 实际覆盖 = −114.9° … +115.2° = **230°** → **空洞 130°**

官方那个「252°」是**把五个相机 FOV 直接相加**（5 × 50.4），
重复计入了相邻 5° 的重叠。**真实方位覆盖只有 230°。**

**对 mask 面积的影响（必须让 koi 在量产前知道）**：

```
AV2 一个样本：       7 条接缝带           ≈ 21.5% 黑
Waymo Percep 样本：  4 条接缝带 ~12%
                   + 130° 车后空洞 36.1%  ≈ 48% 黑
```

**Waymo Perception 的样本会有接近一半是黑的**，是 AV2 的两倍多。
koi 的设计（0731:95「252 度我就只专心在这里，后面两个就算是生的」）依然成立，
但 48% 这个数字他没见过，**属于 B7 眼验时必须说明的信息**。

### 2.2 ✅ 反而是好消息：Perception 的接缝应该比 AV2 更好接

rig 半径 **0.130 m**，小于 AV2 的 0.209–0.378 m。视差 = 基线 / 深度，
**基线更小 ⇒ 接缝矛盾更小**。DB-239 定位的「立柱鼓包」这类问题在 Perception 上应更轻。

### 2.3 ⚠️ 两项适配工作是硬的，不是可选的

**(a) 去畸变 —— Perception 必做**

AV2 管线 `SC._project` 是纯 pinhole。Perception 的 `k1 = 0.347`：

```
图像边缘 r/f = 960/2055 = 0.467
径向位移 ≈ k1·(r/f)² = 0.347 × 0.218 = 7.4%  →  边缘约 71 px
```

**71 px 比整条接缝带（58–68 px）还宽**。不去畸变，接缝位置会整体算错。
E2E 的 `k = 0.0736` → 边缘约 **6.8 px**，超过 4 px 裙边，同样要处理。
（nuScenes 官方原图**已去畸变**，唯一零成本的。）

**(b) E2E 没有逐相机时间戳 ⇒ 无 EMC。已量化代价，可用裙边补偿**

在 AV2 上做了 EMC vs 静态的对照：

| | 条宽 | 实测矛盾漏网 |
|---|---|---|
| EMC（koi 认可版） | 58/60/61/62/63/68/68 | **0** |
| 静态（模拟 E2E） | 56/59/59/62/63/67/67 | **9 px** |

**每对最多窄 2 px。** 把 `SKIRT_PX` 从 4 提到 **6** 即可覆盖，
代价是 mask 多约 0.7%。**这是一个参数，不是一个障碍。**
