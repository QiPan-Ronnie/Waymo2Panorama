#### 色差三层(全部第一性,互相正交)

原模型:`solve_gains_for` 把相机 j 相对 i 建模为**每通道一个乘性标量**,用共视 LiDAR 点的 `median(log I_j − log I_i)` 估计。四条承重假设:(a) 朗伯 (b) 无渐晕 (c) 无加性杂散光 (d) **共视点配准正确**。

1. **`GAIN_MIN_CORR=0.30`(DB-203)** —— 破的是 (d)。判据本身第一性:**曝光比在 log 域是常数偏移,常数偏移不可能破坏相关性**,所以 `corr(log I_i, log I_j) ≈ 0` 就是"这些点不在同一表面"的直接证据。实测 00a6ffc1 a100 的 side_right|front_right:corr **0.029**、IQR 1.615、鲁棒斜率 **−0.027**、共视点中位距离 **6.1m**(ERP 重叠带只有 ~8°,近距离 = 视差极大);同帧其余六对 0.47–0.95,健康 log 全部 0.372–0.862。
2. **`GAIN_PRIOR_W=0.05`(DB-203b)** —— **剔除一条边不是中性操作**:剩余图会绕 6 跳路径推那对的相对曝光,误差累积(实测 a099 那条缝反而 22.0 → **38.0**)。所以被拒的对不退出方程,而是以弱权重加"无相对曝光差"的先验。**一个量不可测时,诚实的退路是先验,不是长程推断。**
3. **`GAIN_PER_CHANNEL=False`(DB-208)** —— **最干净的一条,因为它是减法**。曝光差 = 三通道共同偏移(任意表面可估);白平衡差 = R/B 相对 G 的偏移,**估它需要中性色参照,而共视点落在什么颜色的表面上就带什么颜色**。决定性证据:健康帧上 per-channel 解出的 R/B 比在七台相机上都是 **0.974–1.043**(即它从未找到任何白平衡差要修),只在证据变差时才摆到 0.898 → **per-channel 那三个自由度从来没拟合真实 AWB,只在拟合噪声**。

## 3. ⚠️ 方法教训(这些比结论更值钱)

1. **修复 vs 调参要区别对待**:几何错误的修复(DEPTH_SEAMRAMP)单场景可判;**调参类改动必须跨 log 验证**。DB-184b 的 `GAIN_STRENGTH=0.5` 在 00a6ffc1 三帧上是"双轴帕累托全赢",到三个新 log 上**全线翻车**(5.50→7.33 / 9.08→14.17 / 6.33→7.67),已回退(DB-198)。
2. **眼睛和数字冲突时,先怀疑度量**。旧的接缝度量把每条缝钉在**一个列**上、只采样"该列恰好是领地边界的行"——领地边界是**曲线**,大部分行没被测到:肉眼 21 luma 的台阶被算成 1.0。正确做法在 `db198_seam2.py`(逐行沿边界走,每缝 200+ 样本)。**所有用旧度量得出的接缝数字作废。**
3. **领地图必须用每个 log 自己的标定**。复用别的 log 的 `terr_map` 会把 `rear_right|rear_left` 的缝算到 θ=−76°(几何不可能),整批数字作废。`C = 7 相机在 ego 系位置的质心`,纯标定量,`db197_terr.py` 本地可算。
4. **归因前先算几何**。我两次把"单相机领地内的问题"误判成"骑缝",都被用户证伪。ERP 约定:`theta = 180 − (u+0.5)/W·360`;side_right 覆盖 [−130.1°, −67.7°],front_right 到 −76.4° 即止。
5. **复现 bug 必须对齐输入数据**。DB-163~171 那个黑块五次误诊都没复现,钥匙是:band-only 走的是**选择性下载(不含 annotations)**,机制空转。
6. **worker 会把 per-case 异常吞进 manifest,进程 rc 仍是 0**。**断言必须检查产物存在**,不能只看 rc(我自己又踩了一次)。

- 用户按需提供 Colab(L4 / A100 / G4),cloudflare 隧道远程驱动。**凭据只写 `~/.waymo2panorama/runtime/active_url_5.json`(A100)或 `active_url_l4.json`(L4),绝不进仓库。**
- 隧道常断(HTTP 530 / `getaddrinfo failed`),断了**向用户要新 JSON**
- 驱动:`dr2.get("a100"|"l4")` → `_exec` / `dr_launch` / `dr_wait` / `dr_pull`(模块在 session scratchpad,`dr2.py`)
- **数据不经本地**:AV2 从公共 S3 直接下到 VM(`s5cmd --no-sign-request --numworkers 24`,一个 log 1–3 min)。**Drive 上只有成品,没有原始传感器数据。**
- **★GPU 硬校验**(用户两次抓到空转):GPU job 发射后 150s 检查 `nvidia-smi`,<10% 立即报错并甩完整 log
- **worker 路径是写死的**:数据必须放 `/content/localav2/val/<uuid>`,放别处 worker 报 FileNotFoundError 但 **rc 仍为 0**

### 内核部署定式

- bundle:`Drive/koi_waymo2pano_colab/bundles/w2p_bundle8_relay.zip`,解压出**两棵树**(`/content/waymo2panorama` 原始 + `w2p_ego` 工作),**双树都可能要 patch**
- md5 链:base `cebab759a30a1af56f88d694ea6bd182` → v11 patch `cca4f0c586a2d91abe14d4b121824cf4`
- **推荐做法(DB-192 起)**:直接把 repo 的 `db89_ghost_recovery.py` base64 分块上传覆盖,然后 md5 对比本地——**这样跑的就是 git 里的代码,零歧义**。分块 60000 字符,`cat >> file <<'EOFB'`(`printf %s` 会吞内容)

### 纪律(用户铁律)

1. **每张产出图必须视觉目检**,不许只信指标
2. **凡报结果必附文件路径**
3. 原数据集文件永不修改,新产物只增量添加
4. Drive 更新用**同名 cp 覆盖保 fileId**(mv 会毁分享链接)
5. 每轮改进即 commit + push main;**推前先 fetch**(两条 agent 线并行,main 会分叉)
6. 新实验方向先在 `decision_briefs.md` 开 brief(含 Kill criteria + Max scope);完成后归档进 `progress.md` 并在 briefs 留一行
7. **所有回复和可见推理用中文**

### 其他已知坑

- 空 annotations 表崩内核(`boxes_at` 对标注时刻 argmin)→ 无标注数据集先塞地下 50m 哑框
- per-case 异常被吞成一行 → worker extra rep 注入 `traceback.format_exc()` 拿全栈
- **pkill 杀友军**两变体 → 定式 = pkill 独立小 job + 模式用变量拼接(`P1='xxx'; pkill -f "${P1}[.]py"`)
- Waymo 授权双坑:Colab 浏览器登录 ≠ VM 凭据(需 `auth.authenticate_user()`);waymo.com 注册账号必须与 Colab 账号一致;老 `gsutil` 不读 gcloud 凭据,**用 `gcloud storage`**
- Drive ↔ Colab 同步有延迟,写完别立刻 tight-loop 搜索
